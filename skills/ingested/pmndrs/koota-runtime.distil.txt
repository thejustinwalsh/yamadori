# Koota Frame Loop and Systems
- DO: give every system the world as its first parameter and keep systems free of React imports, one file per system.
  source: "Systems query the world and update entities. Always take `world: World` as first parameter."
- DO: keep time in a singleton Time trait passed to createWorld(Time, ...), read with world.get(Time), with delta in seconds capped at 0.1 to prevent large jumps.
  source: "`delta` capped at 0.1s to prevent large jumps"
- DO: call updateTime(world) first in the frame loop, then the other systems in a fixed order.
  source: "Call `updateTime(world)` first in frameloop"
- WHEN input is continuous (pointer, keyboard, viewport): store it in traits from the event handler (world.set(Pointer, ...)) so frame-loop systems can read it.
  source: "**1. Capture for frameloop:** Store event data in traits so frameloop systems can read it. Use for continuous input (pointer, keyboard, viewport)."
- WHEN an event is discrete (a state machine transition, a network message, an entity lifecycle event): run the system logic when the event fires.
  source: "**2. Run on transition:** Execute system logic immediately when an event fires. Use for discrete events (state machine transitions, network messages, entity lifecycle)."
- DO: make a direct mutation callable from several places an action, and "when X happens, do Y" logic (createAdded, createChanged) a system.
  source: "**Litmus test:** if it's a direct mutation callable from multiple contexts, it's an action."
