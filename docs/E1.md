# E1: the embedding-head classifier, Yamadori's decision layer

Written 2026-09-24. **E1** is a registry of small logistic heads, one per
decision, all reading ONE embedding of the request from the `embeddings`
model already resident on the A4000 (Qwen3-Embedding-0.6B). It is built to
replace Laya. The operator's instruction was: if E1 works, adopt it. Keep
Laya only if E1 narrowing plus Laya picking beats E1 alone; otherwise retire
Laya, use E1, collect more data and self-tune.

## Verdict: E1 alone. Retire Laya.

- **E1 beats Laya's head on both held-out sets.**
  - Set 1: 104/120 against 80/120, 31 vs 7 discordant, exact McNemar
    **p = 0.0001**.
  - Set 2, new and blind-labelled: 110/141 against 86/141, 43 vs 19
    discordant, **p = 0.003**. The same sign repeats on a set no one had
    looked at.
- **No combination with Laya beats E1 alone.** Five arms were
  pre-registered (§3). None beats E1 on set 1: the best is 107 vs 104,
  p = 0.51. Laya choosing between E1's top two is significantly **worse**:
  93 vs 104 (p = 0.027) with its trained head, and 84 vs 104 (p = 0.001)
  zero-shot.
- **E1 is on par with the rule plus symbol lookup, not better.** Against
  `selection.decide` with no second signal, E1 scores 104 vs 91 on set 1
  (p = 0.053) and 110 vs 108 on set 2 (p = 0.87). Neither is significant.
- **Cost.** E1 adds no system and no VRAM: it reads the embedder retrieval
  already keeps loaded. Retiring Laya frees its A4000 share and a process,
  a venv and a port.

**Status against the replacement bar** (docs/CLM-EVAL.md §5, applied to E1
vs Laya):

| bar item | result |
|---|---|
| beats Laya, p < 0.05, held-out 120 | **yes**: 104 vs 80, p = 0.0001 |
| repeats in-set (CV beats Laya in ≥ 6 of 8 seeds) | **yes**: CV 0.779–0.830 on all 8 seeds, against Laya's 0.728 |
| repeats on set 1 across 8 fold seeds | **yes**: 104/120 on all 8 seeds (stable grid), p = 0.0001 each |
| held-out set 2 gives the same sign | **yes**: 110 vs 86, p = 0.003 |
| live service reproduces the offline argmax | **not run**: written as `mcp/test_live_stack.py` `e1` (§8), to run after the deploy |
| operator decision | E1 alone. The combination arm failed (§3) |

The proxy flag `YAMADORI_E1` stays **off by default** until the live check
passes. The retirement plan (§9) is a checklist for after that. Nothing in
it has been executed.

## 1. What was built

`mcp/e1.py` holds four things:

- the head registry
- the fitter: numpy, no torch in the worker
- the artefact store, with versions, promotion and revert
- serving and the self-tuner

| head | labels | status | label source |
|---|---|---|---|
| `route_in` | investigate / answer_directly / clarify | **v1 served** | the 289 labels Laya's head used (`bench/laya_routing_labels*.jsonl`) |
| `escalate` | escalate / continue | untrained: the rule decides | `deep_decisions` outcomes (struggle rows) |
| `kickoff` | plan / act | untrained: the rule decides | `deep_decisions` outcomes (new-task rows) |
| `skill_applies` | applies / not_applies | untrained: stages 1–3 and the fallback decide | `index/skills/router_labels.jsonl` (skill_learn's fallback records) |

**One embedding per request.**

- The text embedded is `render(question, context)`. That is byte for byte
  Laya's route_in state (`laya_head.render_state`, asserted in
  `mcp/test_e1.py`), with `code_search.embed`'s query instruction in front.
- The call goes through `code_search.embed`, so the `gpu_room` lease applies
  and nothing is loaded that is not already resident.
- Vectors are cached per text, in an in-memory LRU of 512 and in
  `index/e1/vectors.sqlite3`.
- `escalate` appends six struggle counts and `kickoff` appends
  log(1 + spec tokens). `skill_applies` reads the product of the request
  and skill vectors plus their cosine.

**Artefacts.**

- Each head version is stored as `index/e1/heads/<head>/vNNNN.json`, which
  holds:
  - the weights: float32, base64, sha256-checked
  - the training n and per-label counts, plus sources
  - the CV accuracy, the weight decay chosen, the fold seed and the date
  - the evaluation that promoted or rejected the version, and its status
- `state.json` names the current version and logs every promote and revert.
- Every version is kept, and `index/` is gitignored, like `index/laya`.

**When a head is not served.** A head returns `None` and the caller's rule
decides in any of these cases:

- fewer than `MIN_TRAIN_N` = 40 labels
- fewer than two labels with ≥ `MIN_PER_LABEL` = 8 each
- an artefact whose feature contract (embedding model, instruction hash,
  render revision, extras) differs from what is served

Both minimums are **choices, not measurements**.

**The fit.**

- It is `scripts/train_laya.py`'s `_fit_linear` reimplemented in numpy:
  - standardise, with unbiased std
  - zero init
  - full-batch Adam, lr 0.05, L2 on weight and bias
  - 600 steps, folded into one affine map
- Weight decay is chosen by 5-fold CV using train_laya's `kfold`,
  reproduced exactly (the test asserts equal folds).
- At wd 0.01 the numpy fit and torch agree to 1.1e-6 in probability, and
  on 120/120 held-out argmaxes (`bench/e1/results/stability.json`).

**A finding: the high decays are numerically unstable.**

- At wd 0.1 and 1.0, Adam at lr 0.05 never settles, so the final iterate
  is float noise:

  | wd | f32 vs f64 same argmax (of 120) | numpy vs torch same argmax (of 120) |
  |---|---|---|
  | 1e-3 | 120 | 120 |
  | 1e-2 | 120 | 120 |
  | 1e-1 | 89 | 98 |
  | 1.0 | 109 | 109 |

- **Consequence.** TEV1-EVAL's "8 seeds 99–106" included seeds whose CV
  picked 0.1 or 1.0, and those cells are noise.
- **Change.** E1's grid is cut to {1e-3, 1e-2}, and the served v1 uses
  1e-2.

**MLP: not adopted.**

- A one-hidden-layer MLP (64 ReLU, torch, same folds) was run against the
  logistic head over 8 fold seeds, paired on out-of-fold predictions.
- Mean out-of-fold accuracy: 0.810 vs 0.802. The MLP was ahead on 5
  seeds, tied on 1 and behind on 2.
- **Significant on 0 of 8 seeds** (per-seed p ≥ 0.18).
- Its decay was picked on seed 0 from 3 values, a selection the logistic
  head did not get.
- The bar was "only if it beats logistic in CV", read as a paired win on a
  majority of seeds. It was not met, so the heads stay logistic.

## 3. The narrowing experiment: can Laya "play nice"?

**Laya's documented strength** is a closed `choice` over a small set with the
state fixed (AGENTS.md "Laya").

**The arms.** They were defined in `bench/e1/eval_e1.py` (`ARMS`) before
either set was scored. N3 and N4 use a low-margin cut taken from E1's
out-of-fold margins on the **training** rows (25th percentile, 0.709), not
from either held-out set.

**The adoption rule** was set before scoring. A combination is adopted only if
it beats N0:

- with p < 0.05 on set 1
- and is not behind N0 on set 2

Across 5 combinations, Bonferroni puts α at 0.01.

| arm | set 1 (n=120) | vs N0 (N0-only / arm-only, p) | set 2 (n=141) | vs N0 |
|---|---|---|---|---|
| N0: E1 alone | **104** | – | **110** | – |
| N1: E1 top-2 → Laya trained head picks | 93 | 16 / 5, **p = 0.027 (worse)** | 102 | 26 / 18, p = 0.29 |
| N2: E1 top-2 → Laya zero-shot 2-way choice (both orders) | 84 | 28 / 8, **p = 0.001 (worse)** | 108 | 17 / 15, p = 0.86 |
| N3: Laya head only where E1's margin < 0.709 (28 and 54 rows) | 103 | 3 / 2, p = 1 | 110 | 9 / 9, p = 1 |
| N4: as N3, zero-shot | 104 | 4 / 4, p = 1 | 115 | 5 / 10, p = 0.30 |
| N5 (exploratory): average of E1 and Laya probabilities | 107 | 3 / 6, p = 0.51 | 100 | 19 / 9, p = 0.087 |
| Laya head alone | 80 | 31 / 7, p = 0.0001 | 86 | 43 / 19, p = 0.003 |

- **Verdict: no combination passes.** Where Laya is given the decision (N1,
  N2), it makes things worse.
- **N5 and N4.** N5's +3 on set 1 reverses to −10 on set 2. N4's +5 on set
  2 is a tie on set 1.
- **Neither is a result**, by PROTOCOL's repeat rule. The verdict is
  **RETIRE LAYA**.

## 5. Cost

| | measured | n |
|---|---|---|
| E1 head arithmetic (`Head.predict`, CPU) | **p50 0.009 ms, p95 0.010 ms** | 2,400 |
| E1 embedding call, one text, through `code_search.embed` incl. the gpu_room lease | p50 78 ms, p95 123 ms | 550 |
| Laya route_in `/route`, server-side time | p50 56 ms, p95 82 ms | 141 |
| Laya round trip (`live_route_check.txt`) | 66 ms median | 120 |

- **E1's cost is the embedding call**, which is in Laya's range. A request
  that retrieval has already embedded does not share the vector: the texts
  differ.
- **No VRAM is added.** Retiring Laya returns its A4000 share. That share
  has never been measured on its own; it lies between "~1 GiB" and
  ≥ 2,445 MiB (gpu_room `FIXED`).
- **Room was checked before every block of 25 calls.** Each check read the
  A4000's free memory by UUID (≥ 1,331 MiB), confirmed no image server was
  on the card, and confirmed llama-swap reported `embeddings` ready.
- No wait was needed, nothing was loaded or evicted, and the 5060 Ti was
  never touched.

## 6. Wiring (behind `YAMADORI_E1=1`, default OFF)

- **selection.** In `select()` the second signal is `e1.route_signal` in
  place of `laya_signal`. `decide(second="E1")` names it in every reason,
  and `signals.second_signal` records it. With the flag off, the
  byte-for-byte Laya path is unchanged.
  - **Caveat.** The proxy's own path is Phase 0.6: it passes a route and a
    trigger, so `select()` never reaches the two-signal stage. This swap
    matters for the legacy path, which the offline evaluators replay.
- **deep.py (Phase 0.6).** One `e1.consult` per request. It runs when deep
  thinking is allowed, not header-forced, and the request is a user turn or
  has struggle events. It reads every trained head from one vector:
  - **`escalate`**, once trained, decides a struggle in place of the
    threshold: at least one signal, no cooldown.
  - **`kickoff`**, once trained, decides a new task in place of the token
    threshold.
  - **`route_in`** (trained) adds a known-hard **area**: a
    `library_question` it says to investigate, on a user turn. The rule's
    unseen-package area still fires on its own.
  - Every reason says which head decided, its version and n.
  - `signals.e1` carries the choices. The embedded state goes into
    `deep_decisions.e1_state` (a new column, added on first open) for the
    learner.
  - `public()`, `deep.rows()` and the dashboard never carry the state text.
- **skill_select stage 4.** Laya is never called. The trained
  `skill_applies` head injects the `ask` candidates it says apply. Untrained
  means skipped, and the fallback runs as before.
- **The proxy never calls Laya with E1 on.** `e1.laya_allowed()` gates
  every request-path caller:
  - `selection.laya_signal`
  - `skill_select.laya_pick`
  - `shomen._laya`, which raises, per its contract
  - `fanout._choice_averaged`

  `mcp/test_e1.py` patches `urlopen` to fail and asserts no URL is opened.
- **Unmeasured behaviour change.** The E1 area trigger adds deep-thinking
  runs on library questions. How often it would fire on live traffic is
  unmeasured. It is a choice, gated by the flag, and its outcomes are
  labelled like every other trigger's.

## 7. Self-tuning

`deep_learn.handle_learn` (the idle job, cpu lane) now also runs `e1.learn()`.
For each head:

1. Labelled rows are gathered:
   - route_in: the 289 gold rows plus `deep_decisions` outcome rows
   - escalate and kickoff: `deep_decisions`
   - skill_applies: the skill fallback labels
2. Rows whose vector is not in the store are counted and skipped. **The
   learner embeds nothing.** Vectors reach the store when E1 serves, so
   **collecting labels needs the flag on**.
3. When at least `LEARN_MIN_NEW` = 30 rows are ones the current version
   never trained on, a seeded, stratified 30% of those new rows is held
   out. It must have at least `MIN_EVAL_N` = 20 rows.
4. A candidate is fitted on the current version's rows plus the other 70%.
5. The candidate and the current version (or, for an untrained slot, the
   rule) are scored on the held-out rows, which **neither** trained on,
   with an exact McNemar test.
6. The candidate is promoted only if it is ahead **and** p < 0.05. route_in
   also has a gold guard: the candidate must not be significantly worse on
   sets 1 and 2.
7. Every candidate is saved as a version, `promoted` or `kept_old`, with
   its evaluation.

**Reverting and viewing.**

- `e1.revert(head, version)` restores a version; `POST
  /dash/api/deep/e1/revert` does the same from the dashboard.
- `GET /dash/api/deep` carries `e1`: every head and version with n, CV,
  status and evaluation.

**Outcome-to-label mapping.** These are **choices**, stated in
`e1._deep_label`:

| head | row | label |
|---|---|---|
| escalate | helped | escalate |
| escalate | wasted run | continue |
| escalate | missed, or escalated_later | escalate |
| escalate | fine | continue |
| kickoff | (same shape) | plan / act |
| route_in (outcome rows on library_question or prose) | helped, missed, escalated_later | investigate |
| route_in | wasted, fine | answer_directly |
| any | not_helped, skipped, unobserved | not used |

- **route_in outcome labels are proxies.** "Fine" means nobody complained,
  not that nothing needed reading. That is why the gold guard exists.
- **Power.** On a 20–30-row held-out split, p < 0.05 needs roughly 6 net
  discordant rows. Promotion will be rare and slow, which is the intent.
