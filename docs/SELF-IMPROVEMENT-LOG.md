# Self-improvement log

Bonsai 2 27B will not always answer as well as a frontier model. This log is
where every observed shortfall goes, with its evidence, so the stack can be
changed to cover it: a skill, a tool description, a route, a trigger, a check.
Kept alongside the work (operator, 2026-09-24); the plan it feeds is
`SELF-IMPROVEMENT-PLAN.md`.

**Rules.** One row per failure PATTERN, not per incident; add incidents as
evidence. Every row names its evidence (request id / `x_yamadori`, script +
n, transcript) and says whether the cause is the MODEL or OURS -- half of what
looked like model failures today were the proxy. A proposed fix is a
proposal until a paired, repeated measurement says it helps (PROTOCOL.md).
Evidence from benchmarks labels contamination (three.js is in every training
set).

**Fix kinds.** `skill` (compressed DO/WHEN items, `mcp/skills.py`) ·
`description` (a tool's trigger text) · `route` (`mcp/route.py` class) ·
`trigger` (deep-thinking escalation, Phase 0.6) · `check` (deterministic
code check / repair) · `ours` (a proxy or harness bug, not the model).
